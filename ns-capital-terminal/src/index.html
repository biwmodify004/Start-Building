เชื่อม AI ของคุณ

ตั้งค่าผู้ให้บริการที่เครื่อง Windows / VPS ซึ่งรัน Broker Bridge แล้วรีสตาร์ต Bridge เว็บอ่านค่าจาก Bridge ไม่เปลี่ยนโมเดลหรือเก็บ API key ในเบราว์เซอร์

Ollama · Local AI

ติดตั้งและเปิด Ollama ดาวน์โหลดโมเดลที่ต้องการ แล้วใช้ชื่อเต็มจาก ollama list แทน YOUR_MODEL_ID ใน PowerShell:

$env:NS_AI_PROVIDER = "ollama"
$env:NS_AI_BASE_URL = "http://127.0.0.1:11434/v1"
$env:NS_AI_MODEL = "YOUR_MODEL_ID"
py bridge.py --mode mt5

Ollama ต้องรันบนเครื่อง Bridge หรือ API ที่เครื่อง Bridge เข้าถึงได้ มือถือเชื่อมผ่าน Bridge; localhost ของมือถือไม่ใช่คอมพิวเตอร์คุณ

LM Studio

โหลดโมเดลและเปิด Local Server ใน LM Studio แล้วตั้ง PowerShell ก่อนเริ่ม Bridge:

$env:NS_AI_PROVIDER = "lm-studio"
$env:NS_AI_BASE_URL = "http://127.0.0.1:1234/v1"
$env:NS_AI_MODEL = "YOUR_LOADED_MODEL_ID"
py bridge.py --mode mt5
OpenAI-compatible API

ตั้ง NS_AI_PROVIDER=openai-compatible, NS_AI_BASE_URL เป็น HTTPS API base และ NS_AI_MODEL บนเครื่อง Bridge หากบริการต้องใช้ key ให้ตั้ง NS_AI_API_KEY เฉพาะเครื่องนั้น

ดาวน์โหลด Bridge รุ่นล่าสุดจากหน้าบัญชี แล้วกด “ตรวจ AI” เพื่อตรวจเซิร์ฟเวอร์และชื่อโมเดล ปุ่มนี้ยังไม่วิเคราะห์หรือเทรด การวิเคราะห์จะเริ่มเมื่อกด Analyze และส่งจริงเมื่อคุณตรวจและยืนยันคำสั่งเท่านั้น

Ollama และ LM Studio ใช้เรียกโมเดล การเชื่อมต่อไม่ได้เทรนจากประวัติเทรดให้อัตโนมัติ

Backend Risk

คู่มือตั้งค่า ↗

ตรวจที่ Backend ทุกคำสั่งเปิดใหม่และการเพิ่มความเสี่ยง SL · Close และการลดความเสี่ยงยังใช้ได้ · กฎนี้ควบคุมเฉพาะคำสั่งที่ผ่าน Bridge ไม่ควบคุมคำสั่งจาก Terminal/แอปอื่น

Daily Loss = ผลปิดวันนี้รวมต้นทุน + floating ปัจจุบัน (ไม่รวมเงินฝากถอน/เครดิต) · Drawdown ใช้ equity peak ที่บันทึกขณะ Backend ทำงาน ปรับเงินฝากถอน · ความเสี่ยงจาก SL เป็นค่าประมาณ ไม่รับประกันราคาเมื่อเกิด Gap

Daily halt คงอยู่ถึงวันใหม่ตามเวลารีเซ็ต ส่วน DD halt ต้องตรวจบัญชีและตั้งจุดอ้างอิงใหม่ขณะไม่มีสถานะเปิด การบันทึกกฎปกติไม่ล้าง DD halt

จำแนกรายการหลังตรวจ Statement

ใช้กับ Balance/Correction ที่อาจเป็นเงินฝากถอนหรือค่าบริการ ต้องตรวจ Statement ก่อน ข้อมูลโบรกเดิมยังเก็บอยู่และมี Audit log
