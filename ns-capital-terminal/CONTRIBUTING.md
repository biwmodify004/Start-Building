# Working on NS Capital

The application lives in `ns-capital-terminal/` in the `Start-Building` repository. Keep unrelated repository content intact. Root `.github/workflows/ns-capital-ci.yml` validates this subproject; the canonical workflow is also versioned with its Site source.

Run `npm ci`, `npm test`, `npm run test:python`, and `npm run build` from the application directory. Node 22.13+ and Python 3.11+ are required. Python tests use fixture terminals and the standard library; they do not need Windows or the MetaTrader5 package. Production MT5 does.

| Directory | Responsibility |
| --- | --- |
| `src/` | Trading terminal, account UI, journal, PWA and public shell assets |
| `broker-bridge/` | Python gateway, ledger, risk, terminal adapters, model connector and MT4 EA |
| `scripts/` | Reproducible build, safe download packaging and Thai manual rendering |
| `tests/` | Fixture-based data, UI, execution and ledger tests |
| `docs/` | User manual and deployment operations |
| `.github/` | CI and contribution templates |

Changes to order routing, risk, account scope, financial calculations or shared reports need tests for the relevant failure cases. Keep account identity checks before and after asynchronous work. Preserve at-most-once submission, fail-closed new entries, explicit sharing consent and credential role separation.

Keep dependencies pinned in the lockfile. Do not commit `dist/`, runtime databases, backups, `.env*`, gateway credentials or real account records. Build output is generated by `npm run build`; edit source. Update the Thai manual when behavior changes, including limitations rather than aspirational claims.

Use a focused branch and pull request. CI does not execute broker orders. A separate Pages workflow tests/builds/deploys main via Pages OIDC. Keep root workflows and their project-source copies aligned. Google OAuth requires an owner-created Web Client ID and explicit backend allowlist; never bypass identity verification for a missing setup value.
